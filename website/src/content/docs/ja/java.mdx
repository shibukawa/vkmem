Java向けの統合は、小さなランチャーとJUnit 5の拡張です。`vkmem-server`をテスト用JVMの子プロセスとして起動します。コンテナもデーモンも使いません。サーバーはミリ秒単位で起動し、JVMと一緒に終了します。

## インストール

テストを実行するマシンに合わせて、バイナリのclassifierを選びます。`darwin-arm64`、`linux-amd64`、`linux-arm64`、`windows-amd64`、`windows-arm64`のいずれかです。1つのjarに入っているバイナリは1つだけです。開発者のマシンとCIでプラットフォームが違うなら、必要なclassifierをすべて宣言します。

## テストクラスごとに1つのサーバーを使う

`VkmemExtension`は、クラスの前にサーバーを起動し、各テストメソッドの前に`FLUSHALL`を実行し、クラスが終わるとサーバーを止めます。テストメソッドは`VkmemServer`を引数に取れます。

```java
import io.github.shibukawa.vkmem.VkmemExtension;
import io.github.shibukawa.vkmem.VkmemServer;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.RegisterExtension;
import redis.clients.jedis.JedisPooled;

import static org.junit.jupiter.api.Assertions.assertEquals;

class VisitCounterTest {
    @RegisterExtension
    static VkmemExtension vkmem = VkmemExtension.create();

    @Test
    void countsVisits(VkmemServer server) {
        try (JedisPooled jedis = new JedisPooled(server.host(), server.port())) {
            jedis.incr("visits");
            assertEquals("1", jedis.get("visits"));
        }
    }

    @Test
    void startsEmpty(VkmemServer server) {
        assertEquals(0L, server.command("DBSIZE"));
    }
}
```

サーバーの設定は`VkmemExtension.builder(b -> b.args("--maxmemory", "64mb"))`で渡します。テストメソッドの間でキー空間を残したいなら、2番目の引数に`false`を渡します。`VkmemExtension.builder(b -> {}, false)`です。

## 一度準備して、テストごとにforkする

準備に時間がかかる場合は、`VkmemExtension.prepared(...)`でtemplateを一度
だけ準備し、各テストメソッドへ新しい`Fork`（`VkmemServer`として受け取る）を
注入できます。

```java
import java.time.Duration;

@RegisterExtension
static VkmemExtension vkmem = VkmemExtension.prepared(
    template -> template.command("SET", "prepared", "yes"),
    4,
    Duration.ofSeconds(30));

@Test
void startsWithPreparedData(VkmemServer server) {
    try (JedisPooled jedis = new JedisPooled(server.host(), server.port())) {
        assertEquals("yes", jedis.get("prepared"));
        jedis.set("test-only", "yes");
    }
}
```

低レベルAPIは`template.snapshot(4).fork()`です。スナップショットがコピーする
のはシリアライズされたキー空間で、クライアント接続や実行時状態はコピーしません。
forkを閉じるとslotが解放され、timeoutを`null`にすると無期限で待ちます。

## JUnitを使わない場合

`VkmemServer`は`AutoCloseable`です。

```java
try (VkmemServer server = VkmemServer.builder().args("--maxmemory", "64mb").start()) {
    Jedis jedis = new Jedis(server.host(), server.port());
    jedis.set("greeting", "hello");
    jedis.close();
}
```

## ビルダーとサーバー

| ビルダーのメソッド | 意味 |
|---|---|
| `port(int)` | `127.0.0.1`のTCPポート。既定では空いているポートを選ぶ |
| `unixSocket(String)` | Unixソケットのパス。既定では一時パスを生成する |
| `noUnixSocket()` | TCPだけで待ち受ける |
| `args(String...)` | `valkey-server`への追加の引数 |
| `binary(Path)` | 同梱のものの代わりにこの`vkmem-server`を使う |
| `quiet(false)` | Valkeyのログを標準エラーに流す |
| `startupTimeout(Duration)` | 既定は30秒 |

起動したサーバーには`host()`、`port()`、`address()`(`host:port`)、`url()`(`redis://127.0.0.1:port`)、`unixSocket()`、`valkeyVersion()`があります。`command(String...)`は新しい接続でコマンドを1つ送り、`String`、`Long`、`List`、`null`のいずれかを返します。エラー応答なら`VkmemException`を投げます。テストの下準備のためのもので、テスト対象のコードには本物のクライアントを使ってください。`flushAll()`は`command("FLUSHALL")`と同じです。

Unixソケットを使うには、それに対応したクライアントが要ります。たとえばNettyのネイティブトランスポートを入れたLettuceです。JVMでは、どこでも動くループバックのTCPを選ぶのが無難です。

## バイナリの取得元

ランチャーはまずシステムプロパティ`vkmem.server.bin`を見て、次に環境変数`VKMEM_SERVER_BIN`、最後にクラスパス上の`vkmem-server-binaries`のclassifier付きjarを探します。同梱のバイナリは、初回に一時ディレクトリへ展開します。プロセスは、`close()`が呼ばれたとき、JVMが終了して標準入力が閉じたとき、親プロセスが消えたときに終了します。
